Library

Rust API

Nib is both a CLI and a library. Add nib-rs to a project to train, quantize, load, and generate with the same code paths the binary uses.

Add the dependency

[dependencies]
nib-rs = { path = "../nib-ai" }
anyhow = "1"

Or from Git:

[dependencies]
nib-rs = { git = "https://github.com/Vamshavardhan50/nib-ai.git" }
anyhow = "1"

The library crate name is nib_rs (Cargo converts the hyphen).

Tokenizer

The tokenizer is character-level. It sorts and deduplicates every character in the training text, then maps each one to an index.

use nib_rs::Tokenizer;

let text = std::fs::read_to_string("shakespeare.txt")?;
let tok = Tokenizer::from_text(&text);
println!("vocabulary: {} characters", tok.vocab_size());
tok.save("tokenizer.json")?;

let ids = tok.encode("ROMEO: ");
let back = tok.decode(&ids);
assert_eq!(back, "ROMEO: ");

Unknown characters map to index 0 when encoding. Keep the tokenizer that was built with a model; vocab size mismatches are rejected by the CLI and server.

CharLM: train and sample

use nib_rs::{CharLM, ModelConfig, Tokenizer, Trainer};

fn main() -> anyhow::Result<()> {
    let text = std::fs::read_to_string("shakespeare.txt")?;
    let tok = Tokenizer::from_text(&text);
    tok.save("tokenizer.json")?;

    let config = ModelConfig {
        vocab_size: tok.vocab_size(),
        context: 16,
        embed_dim: 32,
        hidden_dim: 128,
        ..Default::default()
    };
    let mut trainer = Trainer::new(CharLM::new(config), "sgd".into(), 0.1);

    let ids = tok.encode(&text);
    let context = trainer.model.config.context;
    let mut windows = Vec::new();
    for i in 0..ids.len().saturating_sub(context) {
        windows.push((ids[i..i + context].to_vec(), ids[i + context]));
    }

    for epoch in 0..5 {
        let mut loss = 0.0;
        let mut batches = 0;
        for batch in windows.chunks(32) {
            loss += trainer.train_step(batch);
            batches += 1;
        }
        println!("epoch {epoch}: {:.4}", loss / batches as f32);
    }
    trainer.save("model.json")?;
    Ok(())
}

Sampling uses the model's own sample helper:

use nib_rs::{CharLM, Tokenizer};

let mut model = CharLM::load("model.json")?;
let tok = Tokenizer::load("tokenizer.json")?;
let context = model.config.context;

let mut ctx = tok.encode("ROMEO: ");
if ctx.len() > context {
    ctx = ctx[ctx.len() - context..].to_vec();
}
while ctx.len() < context {
    ctx.insert(0, tok.char_to_id.get(&' ').copied().unwrap_or(0));
}

let mut out = String::from("ROMEO: ");
for _ in 0..200 {
    let probs = model.predict(&ctx);
    let next = CharLM::sample(&probs, 0.7);
    out.push(tok.id_to_char.get(&next).copied().unwrap_or('?'));
    ctx.remove(0);
    ctx.push(next);
}
println!("{out}");

TurboLM: low-rank training

use nib_rs::{turbo, Tokenizer, TurboConfig, TurboLM, TurboTrainer};

let tok = Tokenizer::load("tokenizer.json")?;
let config = TurboConfig {
    vocab_size: tok.vocab_size(),
    context: 64,
    embed_dim: 128,
    hidden_dim: 12114,
    rank: 30,
};
let model = TurboLM::new(config);
println!("logical: {}", model.logical_params());
println!("stored:  {}", model.stored_params());

let mut trainer = TurboTrainer::new(model, 0.05);
// let loss = trainer.train_step(&batch);
trainer.save("turbo.bin")?;

let mut model = TurboLM::load("turbo.bin")?;
let text = turbo::generate_text(&mut model, &tok, "ROMEO: ", 200, 0.7);
println!("{text}");

TurboTrainer::train_step accepts &[(Vec<usize>, usize)]: one context window and one next-token target per sample. It processes the batch as matrices, which is much faster than a per-sample loop.

DenseLM: load, generate, prune, train

use nib_rs::{dense, Tokenizer};

let tok = Tokenizer::load("tokenizer.json")?;

// Load a 4-bit dense artifact (nib.bin or any dense file).
let mut model = dense::load_int4("nib.bin")?;
println!("params: {}", dense::params(&model.config));
println!("file bytes: {}", dense::quantized_bytes(&model.config));

let text = dense::generate_text(&mut model, &tok, "ROMEO: ", 120, 0.7);
println!("{text}");

// Prune hidden units by outgoing fc2 weight norm.
let smaller = dense::prune_hidden(&model, 10902)?;
dense::save_int4(&smaller, "nib-90m.bin")?;

Fine-tune a dense model with DenseTrainer:

use nib_rs::dense::{self, DenseTrainer};

let mut trainer = DenseTrainer::new(dense::load_int4("nib.bin")?, 0.01);
let batch: Vec<(Vec<usize>, usize)> = vec![
    (vec![0; 64], 1),
];
let loss = trainer.train_step(&batch);
println!("loss: {loss:.4}");
trainer.save("nib.bin")?;
Memory

Loading a dense model expands 4-bit weights into f32 matrices. A 90M model needs roughly 360 MB for weights alone, plus activations and gradients during training. Training holds multiple copies of the large matrices; allow well over 1 GB for comfortable dense fine-tuning.

Build dense from Turbo

use nib_rs::{dense, TurboLM};

let turbo = TurboLM::load("turbo.bin")?;
let full = dense::from_turbo(&turbo);
assert_eq!(full.config.hidden_dim, turbo.config.hidden_dim);
dense::save_int4(&full, "dense-100m.bin")?;

from_turbo materializes W = U·V for both low-rank layers. The result is a normal dense CharLM; predictions match the Turbo model up to f32 rounding.

VisionCNN

use nib_rs::{load_image, load_manifest, VisionCNN, VisionTrainer};

let entries = load_manifest("manifest.txt")?;
let (path, label) = &entries[0];
let image = load_image(path, 32, 32, 3)?;

let model = VisionCNN::new(3, 32, 32, 2);
let mut trainer = VisionTrainer::new(model, 0.01);
let loss = trainer.train_step(&[image], &[*label]);
println!("loss: {loss:.4}");
trainer.save("vision.json")?;

Manifests contain one path label pair per line. load_image resizes to the requested height/width, converts to the requested channel count, and normalizes pixels.

Serve from Rust

nib_rs::web::serve("nib.bin", "tokenizer.json", "127.0.0.1", 8080)?;

serve blocks forever and auto-detects Turbo or dense models. To embed the UI in another service, call nib_rs::web::index_html() for the static HTML string.

File formats

FormatMagicPrecisionNotes
TurboCTURBO01int8 per matrixLow-rank factors, biases, embedding
DenseCDENSE4\04-bit + one f32 row scaleVersion 1; full dense matrices
CharLMJSONf32Human-readable, easy to inspect
VisionCNNJSONf32Human-readable

Dense quantization stores each weight as a signed 4-bit nibble in -7..7, scaled by max_abs / 7 per row. Biases stay f32. The header records dimensions so a mismatched file is rejected before inference. Formats are versioned; treat them as internal unless you pin a version.

Threading

predict, train_step, and generate_text take &mut self. Wrap a model in std::sync::Mutex to share it across threads. The built-in server does exactly that, which serializes generation while still allowing concurrent connections. 

use std::sync::{Arc, Mutex};

let model = Arc::new(Mutex::new(nib_rs::dense::load_int4("nib.bin")?));
let shared = Arc::clone(&model);
std::thread::spawn(move || {
    let mut model = shared.lock().unwrap();
    // model.predict(...)
});
