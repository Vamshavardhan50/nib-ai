Four model families

ModelWhat it isArtifactCommands
CharLM A plain character-level MLP with JSON weights. Small, readable, fully configurable. model.json train, generate
TurboLM A low-rank 100M-shape model. 994,572 independent stored weights, int8 on disk. turbo.bin · 994,656 bytes turbo-info, turbo-train, turbo-generate
DenseLM A true dense model: 90,004,008 independent weights, 4-bit on disk. nib.bin · 45,117,066 bytes dense-info, dense-build, dense-train, dense-generate
VisionCNN A convolutional image classifier. 1,898 weights at 16×16 with 10 classes. vision.json vision-train, vision-predict

All four start from random weights and learn from data you provide. No pre-trained checkpoint, GGUF, ONNX file, or external model artifact is loaded.

Text training and generation

CharLM: the readable baseline

Use CharLM when you want to read or modify the whole pipeline. It is a plain MLP with JSON weights, so you can inspect every number. It is the simplest model to read and modify, and the best starting point for learning. 

nib train --input shakespeare.txt --output model.json --tokenizer tokenizer.json --context 8 --hidden 64 --embed 16 --lr 0.1 --epochs 200 --optimizer sgd
nib generate --model model.json --tokenizer tokenizer.json --seed "ROMEO: " --length 200 --temperature 0.8
FlagDefaultUse
--context8Characters of history per prediction
--hidden64MLP hidden width
--embed16Character embedding width
--lr0.1Learning rate
--epochs200Training passes
--optimizersgdsgd or adam

TurboLM: the fast, compact model

Turbo is the interactive choice. It keeps a 100M-entry shape as two low-rank factors (rank 30) and stores them as int8, so the file is under 1 MB. Generation is roughly two orders of magnitude cheaper than dense. 

nib turbo-info --tokenizer tokenizer.json
nib turbo-train --input shakespeare-200k.txt --output turbo.bin --tokenizer tokenizer.json --target 100000000 --context 64 --embed 128 --rank 30 --lr 0.05 --epochs 5 --batch-size 32 --max-samples 0
nib turbo-generate --model turbo.bin --tokenizer tokenizer.json --seed "ROMEO: " --length 200 --temperature 0.7

Real turbo-info output for the shipped shape:

Turbo compact language model
shape: vocab=62 context=64 embed=128 hidden=12114 rank=30
logical (dense) parameters: 100009068 (100.01M)
stored parameters:          994572 (0.995M)
estimated file size:        994656 bytes (0.995 MB)
dense f32 equivalent:       400.0 MB
compression vs f32:         402x

DenseLM: the real 90M-weight model

Dense stores every weight, quantized to 4 bits with per-row scales. It is the artifact to use when you need a genuine dense model under 50 MB, not a low-rank approximation. It is much slower per character. 

nib dense-info --tokenizer tokenizer.json --hidden 10902
nib dense-build --turbo turbo.bin --output dense-100m.bin --tokenizer tokenizer.json
nib dense-train --input shakespeare-200k.txt --output nib.bin --tokenizer tokenizer.json --init-dense dense-100m.bin --hidden 10902 --lr 0.02 --epochs 3 --batch-size 128 --max-samples 20000
nib dense-generate --model nib.bin --tokenizer tokenizer.json --seed "ROMEO: " --length 120 --temperature 0.7

Real dense-info output for the shipped model:

Dense language model (4-bit)
shape: vocab=62 context=64 embed=128 hidden=10902
dense parameters:          90004008 (90.00M)
4-bit file estimate:       45117066 bytes (45.12 MB)
dense f32 equivalent:      360.0 MB

Resume, fine-tune, and prune

GoalFlagsBehavior
Continue a dense checkpoint--init-dense existing.binLoads the model and the tokenizer you pass; trains further
Prune then fine-tune--init-dense big.bin --hidden 10902Ranks hidden units by outgoing fc2 row norm, keeps the strongest, restores order, then trains
Keep every hidden unit--init-dense existing.bin --hidden 0No pruning; pure continued training
Expand Turbo into dense--init-turbo turbo.binMaterializes the low-rank factors into dense matrices, then fine-tunes
Train from random weights--target 100000000 --context 64 --embed 128Builds a new tokenizer from the input text
Tokenizer behavior

train, turbo-train, and random-init dense-train build a character tokenizer from the input text and write it to --tokenizer. The --init-turbo and --init-dense paths load the existing tokenizer and require its vocabulary to match the model. Always generate with the tokenizer that belongs to the model.

Sampling controls

FlagEffect
--seedPrompt text. Short prompts are repeated to fill the context; long prompts keep the last 64 characters.
--lengthCharacters to generate.
--temperatureLower is safer and more repetitive; higher is more random. 0.6–0.8 is a good start.
--modelPath to model.json, turbo.bin, or nib.bin.
--tokenizerMust match the model vocabulary.

Size planning and compression

Two calculators let you check a configuration before spending time on training. Both are instant and require no model file.

CommandWhat it reportsExample
nib turbo-infoLogical vs stored parameters, estimated file bytes, f32 equivalent, compression ratio--target 100000000 --rank 30 --tokenizer tokenizer.json
nib dense-infoDense parameter count and 4-bit file estimate for a hidden width--hidden 10902 --tokenizer tokenizer.json
nib dense-buildMaterializes Turbo factors into a true dense 4-bit file--turbo turbo.bin --output dense-100m.bin

Turbo format

  • Magic CTURBO01
  • Int8 weights with per-row scales
  • 994,656 bytes for the shipped shape
  • 100.01M logical / 994,572 stored parameters

Dense format

  • Magic CDENSE4\0
  • 4-bit weights with per-row scales
  • 45,117,066 bytes for 90,004,008 weights
  • Fully dense matrices, not factors

A 100M dense model at 4 bits is 50,128,686 bytes, slightly over 50 MB. Pruning to 10,902 hidden units gives 90,004,008 weights and 45,117,066 bytes. The 100M configuration remains available with dense-build or a random-init dense-train.

Serving, UI, and embedding

Start the server

nib serve --model turbo.bin --tokenizer tokenizer.json --host 0.0.0.0 --port 8080

The server auto-detects Turbo or dense by the first eight bytes. It prints its URLs at startup. Use 127.0.0.1 for local-only access and 0.0.0.0 in Docker or behind a proxy.

Docker and public hosting

No public API is hosted for you

GitHub Pages serves the static UI and docs only. Start nib serve locally or deploy it to a VPS, Render, Railway, Fly.io, Cloud Run, or Docker host. The full endpoint walkthrough, tunnels, HTTPS, and UI connection steps are in HTTP API → What is the endpoint?.

Vision

VisionCNN is a from-scratch convolutional classifier: one image in, one label and one confidence out. It supports binary and small multi-class image classification. It is not OCR: there is no detection, segmentation, or sequence decoder. 

nib vision-train --manifest manifest.txt --output vision.json --image-size 32 --channels 3 --classes 2 --epochs 20 --batch-size 16 --lr 0.01
nib vision-predict --model vision.json --image data/cats/new.jpg --classes classes.txt
ResultValue
Held-out handwritten digits95.33% (286/300)
Training data1,497 images, 10 classes, 16×16 grayscale
Training time13.5 s for 30 epochs
Model file49,200 bytes of JSON

For the single-glyph OCR-adjacent recipe, failure modes, and production OCR alternatives, see Vision & OCR. Vision is CLI/Rust only; nib serve does not load vision.json.

use nib_rs::{CharLM, ModelConfig, Tokenizer, Trainer};

let tok = Tokenizer::from_text("hello world");
let config = ModelConfig { vocab_size: tok.vocab_size(), ..Default::default() };
let model = CharLM::new(config);
let mut trainer = Trainer::new(model, "sgd".into(), 0.1);

let ids = tok.encode("hello world");
let ctx = ids[..trainer.model.config.context].to_vec();
let target = ids[trainer.model.config.context];
let loss = trainer.train_step(&[(ctx, target)]);
println!("loss: {loss:.4}");
let mut model = nib_rs::dense::load_int4("nib.bin")?;
let tok = Tokenizer::load("tokenizer.json")?;
let text = nib_rs::dense::generate_text(&mut model, &tok, "ROMEO: ", 120, 0.7);
println!("{text}");
let mut model = nib_rs::VisionCNN::load("vision.json")?;
let image = nib_rs::load_image("glyph.png", model.input_h, model.input_w, model.input_channels)?;
let probs = model.predict(&image);
let (class, confidence) = probs.iter().enumerate().max_by(|a, b| a.1.partial_cmp(b.1).unwrap()).unwrap();
println!("class {class} at {confidence:.4}");

What it cannot do

Not supportedReason or alternative
Chat, question answering, instruction followingCharacter-level next-token model with no instruction tuning
World knowledge or factual recallOnly patterns in the training corpus
Long context64 characters; longer prompts keep the last 64
OCR or reading text from photosSingle-label CNN only; use Tesseract, PaddleOCR, EasyOCR, or docTR
Object detection or segmentationThe vision model classifies a whole crop
GPU training or inferenceCPU, single thread, ndarray
Token streamingThe API returns the full string
Built-in auth, TLS, or rate limitingPut a reverse proxy in front
100B parameters under 100 MBPhysically impossible: 100B at 1 bit is ~12.5 GB
