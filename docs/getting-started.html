Getting started

From a clean machine to a running model in five minutes. The repository already contains a trained 90M dense model and a compact Turbo model, so you can serve something useful before training anything yourself.

Prerequisites

  • Rust stable (2021 edition). Install with rustup.
  • Windows: the GNU toolchain and MinGW. build.ps1 locates MinGW automatically; plain cargo build also works if your toolchain is configured.
  • No Python, Node, CUDA, or GPU. The server, trainer, tokenizer, and UI are all in the Rust binary.
  • Disk and RAM: about 500 MB for target/; dense inference needs roughly 400 MB of RAM for the f32 weights.
# Windows (PowerShell)
winget install Rustlang.Rustup
winget install BrechtSanders.WinLibs.POSIX.UCRT

# macOS / Linux
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Restart the terminal after installing so cargo is on PATH.

1. Clone and build

git clone https://github.com/Vamshavardhan50/nib-ai.git
cd nib-ai

# Windows: finds MinGW and uses the GNU toolchain
./build.ps1 -Release

# Any platform with cargo on PATH
cargo build --release

The release profile enables LTO, one codegen unit, panic = "abort", and symbol stripping. The resulting binary is about 3 MB.

2. Verify the binary

./target/release/nib version
./target/release/nib --help

# Windows
./target/release/nib.exe version

Expected output includes nib-rs 0.1.0 and the full command list.

3. Run the shipped model

nib.bin is a 45.12 MB dense model with 90,004,008 independent weights. Start the server on localhost: 

./target/release/nib serve --model nib.bin --tokenizer tokenizer.json --host 127.0.0.1 --port 8080

# Windows
./target/release/nib.exe serve --model nib.bin --tokenizer tokenizer.json --host 127.0.0.1 --port 8080

You should see:

nib server listening on http://127.0.0.1:8080/
API: POST http://127.0.0.1:8080/api/generate
model: nib.bin (45117066 bytes, 45.117 MB), CORS enabled

Check that it is alive and inspect the model metadata:

curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/info
{"status":"ok"}

{
  "name": "DenseLM",
  "format": "dense-int4",
  "architecture": "dense MLP, 4-bit weights on disk",
  "logical_parameters": 90004008,
  "stored_parameters": 90004008,
  "file_bytes": 45117066,
  "config": { "vocab_size": 62, "embed_dim": 128, "hidden_dim": 10902, "context": 64 }
}

4. Generate text

Browser UI

Open http://127.0.0.1:8080/. The page detects the model, shows its size, and generates text. It also produces an <iframe> embed snippet that preserves the API endpoint.

CLI

./target/release/nib dense-generate --model nib.bin --tokenizer tokenizer.json \
  --seed "First Citizen: Before we proceed any further, hear me speak." \
  --length 160 --temperature 0.7

HTTP

curl -X POST http://127.0.0.1:8080/api/generate \
  -H "content-type: application/json" \
  -d '{"prompt":"First Citizen: Before we proceed any further, hear me speak.","length":120,"temperature":0.7}'

The prompt is repeated to fill the 64-character context when it is shorter than that. Longer, natural prompts produce the best results. Dense generation takes seconds per short request on a laptop CPU; serve turbo.bin when you need a fast interactive demo.

5. Train your first model (CharLM)

CharLM is the smallest and easiest model. It uses a plain JSON file, trains in seconds to minutes on a laptop, and is a good way to verify the full pipeline. 

./get-data.ps1

./target/release/nib train --input shakespeare.txt --output model.json \
  --tokenizer tokenizer.json --context 12 --hidden 128 --embed 24 \
  --epochs 40 --lr 0.1

Then generate:

./target/release/nib generate --model model.json --tokenizer tokenizer.json \
  --seed "ROMEO: " --length 300 --temperature 0.7
What the loss means

The trainer prints cross-entropy loss. Lower is better; on the 200 KB Shakespeare prefix a small CharLM typically falls from about 2.35 to about 1.46 after 40 epochs. These are training losses, not held-out validation numbers.

6. Train TurboLM

Turbo stores a 100M-entry shape as low-rank factors and quantizes them to int8. It trains quickly and is the best choice for a fast web demo. 

./target/release/nib turbo-train --input shakespeare.txt --output turbo.bin \
  --tokenizer tokenizer.json --target 100000000 --context 64 --embed 128 \
  --rank 30 --epochs 5 --lr 0.05 --batch-size 32

A verified 5-epoch run on the 200 KB prefix went from loss 2.3209 to 1.7765 and produced a 994,656-byte file. 

./target/release/nib turbo-generate --model turbo.bin --tokenizer tokenizer.json \
  --seed "ROMEO: " --length 300 --temperature 0.7

7. Build and prune DenseLM

A dense model starts by materializing the trained Turbo factors into full matrices, then fine-tuning every weight with dense gradients. The shipped model then prunes 1,212 hidden units to land under 50 MB and fine-tunes the remaining sub-network. 

# Materialize the 100M dense model from Turbo
./target/release/nib dense-build --turbo turbo.bin --output dense-100m.bin \
  --tokenizer tokenizer.json

# Fine-tune all 100M weights
./target/release/nib dense-train --input shakespeare.txt --output dense-100m.bin \
  --tokenizer tokenizer.json --init-turbo turbo.bin \
  --epochs 2 --max-samples 20000 --batch-size 128 --lr 0.02

# Prune to 10,902 hidden units and fine-tune the sub-network
./target/release/nib dense-train --input shakespeare.txt --output nib.bin \
  --tokenizer tokenizer.json --init-dense dense-100m.bin --hidden 10902 \
  --epochs 3 --max-samples 20000 --batch-size 128 --lr 0.01

The final file is 45,117,066 bytes with 90,004,008 parameters. Dense training is CPU-heavy: batch 128 is roughly 3× faster than batch 32 on the development machine.

Project layout

nib-ai/
  src/
    main.rs      CLI commands and training loops
    model.rs     Tokenizer, CharLM, generic trainer
    turbo.rs     Low-rank TurboLM and int8 format
    dense.rs     DenseLM, pruning, 4-bit format, dense trainer
    web.rs       HTTP server, JSON API, embedded UI
    vision.rs    CNN, convolution, pooling, image loading
    layers.rs    Linear and Embedding layers
    tensor.rs    Tensor wrappers over ndarray
    optimizer.rs SGD and Adam
  docs/          This static documentation site
  nib.bin        Shipped 90M dense model (45.12 MB)
  turbo.bin      Shipped compact model (994,656 bytes)
  tokenizer.json 62-character vocabulary
  index.html     Static UI export
  Dockerfile     Multi-stage build and runtime image
  get-data.ps1   Public corpus downloader
  build.ps1      Windows GNU build helper

Troubleshooting

SymptomCause and fix
cargo is not recognizedRestart the terminal after installing rustup, or add %USERPROFILE%\.cargo\bin to PATH.
Linker or dlltool errors on WindowsInstall WinLibs MinGW and use ./build.ps1 -Release, which finds it automatically.
bind 0.0.0.0:8080 failedAnother process owns the port. Use --port 8081 or stop the old process. On Windows: Get-NetTCPConnection -LocalPort 8080.
tokenizer vocab (...) does not match model vocabThe tokenizer was built from different text. Use the tokenizer.json that belongs to the model, or retrain both on the same corpus.
is not a nib modelThe file is not a Turbo int8 (CTURBO01) or dense int4 (CDENSE4) artifact. Rebuild it with the commands above.
Generation is very slowExpected for the 90M dense model on CPU. Serve turbo.bin for interactive use, shorten length, or use a faster machine.
413 Payload Too LargeThe request body exceeds 64 KB. Send a shorter prompt or fewer fields.
prompt is limited to 4096 charactersThe API caps prompts at 4,096 characters by design.
GitHub rejects a model fileGitHub blocks files over 100 MB. nib.bin is 45 MB and fits; use Git LFS or Releases for larger variants.
