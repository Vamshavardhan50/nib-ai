HTTP API

nib serve starts a zero-dependency HTTP/1.1 server with a JSON API, CORS, an OpenAPI document, and a browser UI. The same endpoints work for Turbo and dense models.

There is no public API endpoint out of the box

The hosted UI at vamshavardhan50.github.io/nib-ai is static and has no backend. Until you run or deploy nib serve, the only endpoint is on your own machine. This section covers a local URL, a temporary public URL, and a permanent HTTPS endpoint.

What is the endpoint?

The base URL depends on where the Rust process runs. The generation path is always /api/generate.

Where the server runsBase URLWho can reach it
Your machine (local only)http://127.0.0.1:8080Only that machine
Your machine (LAN / Docker)http://192.168.1.20:8080Devices on the same network
VPS or cloud servicehttps://api.example.comAnyone on the internet
Temporary tunnelhttps://random-name.trycloudflare.comAnyone, while the tunnel runs

Local generation endpoint: POST http://127.0.0.1:8080/api/generate. The static UI on GitHub Pages needs a public HTTPS base URL before it can generate anything.

Step-by-step: a local endpoint

1. Get the binary, model, and tokenizer

git clone https://github.com/Vamshavardhan50/nib-ai.git
cd nib-ai
cargo build --release

# Windows: .\build.ps1 -Release

The repository tracks both nib.bin (90M dense, 45.12 MB) and turbo.bin (994,656 bytes), plus tokenizer.json.

2. Start the server

# macOS / Linux — dense model
./target/release/nib serve --model nib.bin --tokenizer tokenizer.json \
  --host 127.0.0.1 --port 8080

# Windows PowerShell
.\target\release\nib.exe serve --model nib.bin --tokenizer tokenizer.json \
  --host 127.0.0.1 --port 8080

Use turbo.bin for a faster demo. Bind 127.0.0.1 for local-only access; bind 0.0.0.0 when a container, reverse proxy, or another device must reach the server.

3. Confirm the endpoint

curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/info

The server prints its own URLs at startup:

nib server listening on http://localhost:8080/
API: POST http://localhost:8080/api/generate
model: nib.bin (45117066 bytes, 45.117 MB), CORS enabled

4. Generate text

curl -X POST http://127.0.0.1:8080/api/generate \
  -H "content-type: application/json" \
  -d '{"prompt":"ROMEO: ","length":80,"temperature":0.7}'

If this works, the endpoint is correct. The browser UI is at http://127.0.0.1:8080/.

Step-by-step: a public HTTPS endpoint

A public endpoint is required for the hosted Pages UI, another website, or a mobile app. Choose one host, then follow the same six steps.

HostBest forHTTPS
Render, Railway, Fly.io, Cloud RunManaged Docker deploy, least server maintenanceProvided
VPS + Caddy or nginxFull control, persistent process, predictable costLet's Encrypt
Cloudflare Tunnel / ngrokA quick demo from your laptopProvided
GitHub Pages, Netlify, VercelStatic UI and docs onlyCannot run the API

1. Build once

cargo build --release

You need three files: the nib binary, nib.bin or turbo.bin, and tokenizer.json.

2. Copy the files to the host

scp target/release/nib nib.bin tokenizer.json user@your-host:/opt/nib/

For Docker, use the included Dockerfile instead of copying files by hand.

3. Run on all interfaces

./nib serve --model nib.bin --tokenizer tokenizer.json \
  --host 0.0.0.0 --port 8080

Keep the process alive with systemd, Docker, or the platform's process manager. 127.0.0.1 is not reachable from outside the machine.

4. Put HTTPS in front

On a VPS, Caddy is the shortest path:

api.example.com {
    reverse_proxy 127.0.0.1:8080 {
        transport http {
            read_timeout 300s
            write_timeout 300s
        }
    }
}

Render, Railway, Fly.io, and Cloud Run terminate TLS for you and give you an HTTPS URL.

5. Test from outside your network

curl https://api.example.com/health
curl https://api.example.com/api/info

curl -X POST https://api.example.com/api/generate \
  -H "content-type: application/json" \
  -d '{"prompt":"ROMEO: ","length":40,"temperature":0.7}'

Test from a phone on mobile data, not just from the same machine.

6. Connect the hosted UI

https://vamshavardhan50.github.io/nib-ai/?api=https://api.example.com

The UI saves the endpoint in localStorage and includes it in the iframe snippet. The API must be HTTPS: an HTTPS page cannot call an HTTP endpoint.

7. Lock it down

The built-in server has no authentication, TLS, or rate limiting, and CORS is *. Add auth and limits at the reverse proxy before making a dense model public. Prefer Turbo for open demos; it is roughly two orders of magnitude cheaper per character.

Temporary public URL with a tunnel

For a demo, you can expose your local server without deploying. The laptop must stay awake, the URL changes each run, and there is no SLA. Do not use this for production. 

# Terminal 1: local server
nib serve --model turbo.bin --tokenizer tokenizer.json --host 127.0.0.1 --port 8080

# Terminal 2: Cloudflare Tunnel (no account needed for a quick tunnel)
cloudflared tunnel --url http://127.0.0.1:8080
# prints: https://random-name.trycloudflare.com

Then open:

https://vamshavardhan50.github.io/nib-ai/?api=https://random-name.trycloudflare.com

ngrok http 8080 works the same way. Both provide HTTPS, so the static UI can call them without mixed-content errors.

How the UI chooses an endpoint

  1. The ?api= query parameter, if present.
  2. The nib-api value saved in localStorage from a previous visit.
  3. The page's own origin, when it is served by nib serve on a non-static host.
  4. Otherwise, an empty endpoint. On GitHub Pages the UI shows “enter an API endpoint”.

Trailing slashes are removed. The API base is stored exactly as entered.

Endpoint troubleshooting

SymptomCause and fix
UI says “enter an API endpoint”You are on a static host with no backend. Start or deploy the API and add ?api=.
Works on the server, not from your phoneThe server is bound to 127.0.0.1. Restart with --host 0.0.0.0 and allow the port in the firewall.
Failed to fetch / CORS errorWrong URL, server down, or an HTTPS page calling HTTP. Use the exact HTTPS base URL.
404 on generationUse POST /api/generate, not GET, and include /api.
Connection refused in DockerBind 0.0.0.0 inside the container and publish the port: -p 8080:8080.
Request times out on denseRaise the proxy timeout to 300 s and shorten length. Use Turbo for interactive traffic.
413 or prompt is limitedBody limit is 64 KB and prompts are capped at 4,096 characters.
Health works but generation is slowExpected for the 90M dense model on CPU. Serve turbo.bin for a fast demo.

All JSON responses use application/json; charset=utf-8. Unknown paths return 404 with a list of valid paths.

CORS

Cross-origin requests are allowed from any origin. The server answers OPTIONS preflight with 204 No Content and includes: 

Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: content-type

This is what lets the static UI on GitHub Pages, Netlify, Vercel, or Cloudflare Pages call a separately hosted Rust API.

POST /api/generate

Request body

FieldTypeDefaultRules
promptstringShakespeare lineOptional; at most 4,096 characters
lengthinteger300Clamped to 1..2000 characters
temperaturenumber0.8Clamped to 0.01..2.0; non-finite values become 0.8

The body is optional. An empty body uses the default prompt and settings. Unknown JSON fields are ignored by serde.

Response

{
  "text": "First Citizen:\nBefore we proceed any further, hear me speak.\n\nSICINIUS:\nBut, so ma",
  "prompt": "First Citizen:\nBefore we proceed any further, hear me speak.\n\n",
  "length": 120,
  "temperature": 0.7,
  "ms": 2787
}

text includes the prompt followed by the generated characters. ms is server-side generation time. The response is sent after generation completes; there is no streaming.

Prompt behavior

Both text models use a fixed 64-character context. If the prompt is shorter, it is repeated to fill the context rather than padded with spaces. If it is longer, the last 64 characters are used. Natural prompts of 64+ characters produce the most coherent text.

Examples

curl

curl -X POST http://127.0.0.1:8080/api/generate \
  -H "content-type: application/json" \
  -d '{"prompt":"First Citizen: Before we proceed any further, hear me speak.","length":120,"temperature":0.7}'

PowerShell

$body = @{ prompt = "ROMEO: "; length = 80; temperature = 0.7 } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/api/generate \
  -ContentType "application/json" -Body $body

Python

import requests

response = requests.post(
    "http://127.0.0.1:8080/api/generate",
    json={
        "prompt": "First Citizen: Before we proceed any further, hear me speak.",
        "length": 120,
        "temperature": 0.7,
    },
    timeout=300,
)
response.raise_for_status()
print(response.json()["text"])

JavaScript (browser or Node 18+)

const response = await fetch("http://127.0.0.1:8080/api/generate", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({
    prompt: "First Citizen: Before we proceed any further, hear me speak.",
    length: 120,
    temperature: 0.7
  })
});
if (!response.ok) throw new Error("HTTP " + response.status);
const data = await response.json();
console.log(data.text);

Limits and concurrency

LimitValue
Request body64 KB
Request headers32 KB
Prompt4,096 characters
Generated length1–2,000 characters
Read timeout30 seconds
Write timeout300 seconds
ConnectionsOne thread per connection
GenerationSerialized by a model mutex

Health checks are cheap, but generation holds the model lock for the whole request. On a dense model, a long request can occupy the server for tens of seconds; plan your proxy timeouts accordingly. There is no request queue, rate limit, authentication, or TLS in the built-in server.

OpenAPI

GET /openapi.json returns an OpenAPI 3.1 document describing the health, info, and generation endpoints. Point Swagger UI, Redoc, or a client generator at it.

curl http://127.0.0.1:8080/openapi.json

Embed the UI

Export the UI with nib web-export, host the HTML on any static host, and set the API base with a query parameter: 

https://your-static-host/?api=https://your-nib-api-host

The UI stores the endpoint in localStorage and includes it in the generated iframe snippet.

<iframe src="https://your-static-host/?api=https://your-nib-api-host"
        width="100%" height="760"
        style="border:0;border-radius:16px"
        title="nib-rs language model"></iframe>

Production notes

  • Put it behind a reverse proxy for TLS, authentication, rate limiting, and request logging. The built-in server is intentionally minimal.
  • Raise proxy timeouts for dense generation. A 300-second upstream write timeout is already set in Rust; Caddy, nginx, or a cloud load balancer may be shorter.
  • Use Turbo for interactive traffic. Dense is the artifact to inspect and benchmark, not the fastest chat backend.
  • Memory: dense needs roughly 400 MB of RAM for f32 weights plus activations; allow 1 GB in containers.
  • No streaming: clients receive the full text in one JSON response.
