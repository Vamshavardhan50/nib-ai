Introduction: what the model is about

Nib is a from-scratch character-level language model. Give it up to 64 characters of text and it predicts the next character. Feed that prediction back in and it writes Shakespeare-style dialogue, code-like text, or whatever pattern its training corpus contains — one character at a time.

It is deliberately not a chatbot and not a general-purpose assistant. There is no attention, no instruction tuning, and no world knowledge. The point is a complete language-model pipeline you can read end to end, train on a laptop CPU, compress into a small file, and embed in a CLI, a Rust program, an HTTP service, or any website.

Nib ships two text artifacts from the same architecture family. TurboLM is a low-rank model with a 100M-entry shape stored in 994,656 bytes. DenseLM is a true dense model with 90,004,008 independent weights stored in 45,117,066 bytes at 4 bits. Both use a 62-character vocabulary and a 64-character context. Turbo is the fast interactive demo; Dense is the artifact that actually stores every weight.

What it is good at

  • Continuing text in a learned local style and format.
  • Learning speaker labels, line breaks, spelling, and small-corpus patterns.
  • Running offline on a CPU with no GPU, Python, or model hub.
  • Teaching the full training and quantization pipeline in readable Rust.
  • Embedding a tiny text model in a website, CLI, or desktop app.

What it is not built for

  • Answering questions, reasoning, or following instructions.
  • General world knowledge or factual recall.
  • Long documents; the context is only 64 characters.
  • Chat, tool use, streaming, or multi-turn conversation.
  • GPU-scale training or production multi-tenant serving without a proxy.

Design principles

Nib is a deliberately small, readable implementation of the whole language-model pipeline. The tensor math, layers, backpropagation, optimizer, tokenizer, training loop, quantization, HTTP server, and browser UI are all in this repository. The only heavyweight dependency is ndarray for array storage and matrix multiplication.

λ

From scratch

Xavier/He initialization, hand-written forward and backward passes, SGD, and cross-entropy. Nothing is downloaded except real training text.

◫

Two text models

TurboLM keeps a 100M-entry shape in under 1 MB. DenseLM stores 90M independent weights in 45 MB at 4 bits.

⇄

One API

nib serve auto-detects either format and exposes the same JSON endpoints, CORS, OpenAPI document, and browser UI.

⌁

Embeddable

Export the UI as one HTML file, host it on GitHub Pages, Netlify, Vercel, or Cloudflare Pages, and point it at your API with ?api=.

▦

Vision too

A from-scratch CNN with convolution, pooling, and backprop for labeled image classification, trained from a simple manifest.

▣

Portable

A single static binary, two model files, and a tokenizer. Docker image included; no runtime, VM, or GPU required.

Quick start

Clone the repository

git clone https://github.com/Vamshavardhan50/nib-ai.git
cd nib-ai

Build the release binary

cargo build --release

# Windows helper (finds MinGW automatically):
.\build.ps1 -Release

Serve the shipped dense model

./target/release/nib serve --model nib.bin --tokenizer tokenizer.json --port 8080

# Windows:
.\target\release\nib.exe serve --model nib.bin --tokenizer tokenizer.json --port 8080

Open the UI or call the API

curl http://127.0.0.1:8080/health
curl -X POST http://127.0.0.1:8080/api/generate \
  -H "content-type: application/json" \
  -d '{"prompt":"ROMEO: ","length":120,"temperature":0.7}'

For the fastest interactive demo, serve turbo.bin instead. Dense inference is roughly one to two orders of magnitude slower on CPU because every generated character touches all 90M weights.

No public API is attached to the hosted UI

GitHub Pages serves static files only. The live UI has no backend until you start nib serve locally or deploy it to a Rust host. Local base URL: http://127.0.0.1:8080. Public endpoint steps, tunnels, and UI connection: HTTP API → What is the endpoint?.

How the pipeline fits together

Textreal .txt corpus
Tokenizercharacter vocabulary
ModelMLP / low-rank MLP
4-bit filenib.bin / turbo.bin
HTTP + UIone static binary

Training and inference share the same code. The dense trainer materializes low-rank factors into full matrices, then updates every weight with dense gradients. Saving quantizes each row to 4 bits with one f32 scale, so the artifact is small but still a normal dense network at load time.

Honest scope

Small model, small corpus

The shipped model is trained on the first 200,000 bytes of Tiny Shakespeare, a public-domain corpus. It is a character-level model with a 64-character context. It learns spelling, speaker labels, line breaks, and short Shakespeare-like phrases; it is not a general assistant. Reported losses are training losses; there is no held-out validation split in the shipped run.

Size is physics, not branding

90M weights at 4 bits is about 45 MB. A 100B-parameter model cannot fit under 100 MB: even 1 bit per weight needs roughly 12.5 GB. Nib targets the achievable end of the size curve, and the math is shown on the models page.
