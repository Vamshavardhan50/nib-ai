Reference

CLI reference

One binary, nib, contains the trainers, generators, HTTP server, static UI exporter, and vision tools. Run nib <command> --help for the same information from the terminal.

Synopsis

nib <command> [options]

Windows users can call ./target/release/nib.exe; every example below uses the portable forward-slash form.

Conventions

  • Short flags exist where noted: -i input, -o output, -m model, -s seed, -e epochs.
  • Paths are resolved relative to the current directory. Run commands from the repository root unless you pass absolute paths.
  • Tokenizers must match the model vocabulary. A 62-token tokenizer cannot load a 65-token model.
  • All training is CPU-only and uses plain SGD. The --optimizer flag on train is accepted but the current training step always applies SGD.
  • Loss is mean cross-entropy over the epoch or logging window. It is a training loss, not validation accuracy.

Text model commands

nib train

Train a small character-level MLP. The tokenizer is built from the input text and saved to the tokenizer path.

FlagDefaultMeaning
--input, -idata.txtTraining text file
--output, -omodel.jsonOutput model path
--tokenizertokenizer.jsonWhere to save the built tokenizer
--context8Characters of context
--hidden64Hidden units
--embed16Embedding width
--lr0.1Learning rate
--epochs, -e200Passes over the training windows
--optimizersgdAccepted for compatibility; SGD is used
 
nib train --input shakespeare.txt --output model.json --tokenizer tokenizer.json \
  --context 12 --hidden 128 --embed 24 --epochs 40 --lr 0.1

nib generate

FlagDefaultMeaning
--model, -mmodel.jsonCharLM JSON model
--tokenizertokenizer.jsonTokenizer file
--seed, -semptyPrompt text
--length200Characters to generate
--temperature1.0Sampling temperature
 
nib generate --model model.json --tokenizer tokenizer.json \
  --seed "ROMEO: " --length 500 --temperature 0.7

Dense commands

nib dense-info

Prints the dense shape, exact parameter count, and exact 4-bit file size. Add --hidden to check a pruned configuration without building it.

FlagDefaultMeaning
--target100000000Parameter target when --hidden is 0
--vocab62Vocabulary size
--context64Context length
--embed128Embedding width
--hidden0Explicit hidden size; 0 derives it from --target
--tokenizernoneRead vocabulary size from a tokenizer file
 
nib dense-info --hidden 10902 --tokenizer tokenizer.json

nib dense-build

Expands a trained Turbo model into full dense matrices (W = U·V). The output has the same predictions as the Turbo model, up to f32 rounding.

FlagDefaultMeaning
--turboturbo.binSource Turbo model
--output, -onib.binDense output path
--tokenizertokenizer.jsonTokenizer for vocabulary validation
 
nib dense-build --turbo turbo.bin --output dense-100m.bin --tokenizer tokenizer.json

nib dense-train

Trains a dense model from random weights, fine-tunes a Turbo expansion, resumes a dense artifact, or prunes and fine-tunes a smaller sub-network. The output is always a complete dense 4-bit file.

FlagDefaultMeaning
--input, -ishakespeare.txtTraining text
--output, -onib.binDense output path
--tokenizertokenizer.jsonTokenizer path
--init-turbononeExpand this Turbo model, then fine-tune all weights
--init-densenoneResume from this dense 4-bit model
--hidden0Random init: derive hidden size. With --init-dense: prune to this size
--target100000000Random-init parameter target
--context64Random-init context length
--embed128Random-init embedding width
--lr0.02Learning rate
--epochs, -e1Training epochs
--batch-size128Mini-batch size
--max-samples20000Windows per epoch; 0 means all
How pruning works

--hidden with --init-dense ranks hidden units by the L2 norm of their outgoing fc2 weights, keeps the strongest units in their original order, and fine-tunes the resulting sub-network. The saved file is fully dense, not low-rank. 

# Fine-tune a 100M dense model from Turbo
nib dense-train --input shakespeare.txt --output dense-100m.bin \
  --tokenizer tokenizer.json --init-turbo turbo.bin \
  --epochs 2 --max-samples 20000 --batch-size 128 --lr 0.02

# Prune to 90M and fine-tune
nib dense-train --input shakespeare.txt --output nib.bin \
  --tokenizer tokenizer.json --init-dense dense-100m.bin --hidden 10902 \
  --epochs 3 --max-samples 20000 --batch-size 128 --lr 0.01

Serving commands

nib serve

Starts the HTTP API, CORS preflight, OpenAPI document, and browser UI. The model format is detected from the first eight bytes, so the same command works for turbo.bin and nib.bin.

FlagDefaultMeaning
--model, -mturbo.binTurbo or dense model
--tokenizertokenizer.jsonTokenizer file
--host0.0.0.0Bind address; use 127.0.0.1 for local-only
--port8080TCP port
 
nib serve --model nib.bin --tokenizer tokenizer.json --host 127.0.0.1 --port 8080
nib serve --model turbo.bin --tokenizer tokenizer.json --host 0.0.0.0 --port 8080

nib web-export

Writes the embedded browser UI to a single HTML file. The page has no build step and no external assets; host it anywhere static and add ?api=https://your-host.

FlagDefaultMeaning
--output, -oindex.htmlDestination HTML file
 
nib web-export --output index.html

Vision commands

nib vision-train

The manifest is one image_path label pair per line. Labels are zero-based integers.

data/cats/001.jpg 0
data/dogs/002.jpg 1
FlagDefaultMeaning
--manifest, -imanifest.txtImage/label list
--output, -ovision.jsonOutput model
--image-size16Square input size
--channels11 = grayscale, 3 = RGB
--classes10Number of labels
--lr0.01Learning rate
--epochs, -e10Training epochs
--batch-size16Mini-batch size
 
nib vision-train --manifest manifest.txt --output vision.json \
  --classes 2 --image-size 32 --epochs 20

nib vision-predict

FlagDefaultMeaning
--model, -mvision.jsonTrained CNN
--image, -irequiredImage to classify
--classesnoneOptional names, one per line
 
nib vision-predict --model vision.json --image data/cats/new.jpg --classes classes.txt

Recipes

Use your own corpus

nib train --input mydata.txt --output model.json --tokenizer my-tokenizer.json \
  --context 24 --hidden 192 --embed 32 --epochs 60

nib turbo-train --input mydata.txt --output my-turbo.bin \
  --tokenizer my-tokenizer.json --context 64 --embed 128 --rank 30 --epochs 5

Produce a 90M model under 50 MB from scratch

nib turbo-train --input shakespeare.txt --output turbo.bin --tokenizer tokenizer.json \
  --context 64 --embed 128 --rank 30 --epochs 5

nib dense-build --turbo turbo.bin --output dense-100m.bin --tokenizer tokenizer.json

nib dense-train --input shakespeare.txt --output dense-100m.bin --tokenizer tokenizer.json \
  --init-turbo turbo.bin --epochs 2 --max-samples 20000 --batch-size 128 --lr 0.02

nib dense-train --input shakespeare.txt --output nib.bin --tokenizer tokenizer.json \
  --init-dense dense-100m.bin --hidden 10902 --epochs 3 --max-samples 20000 --batch-size 128 --lr 0.01

nib dense-info --hidden 10902 --tokenizer tokenizer.json

Resume dense training

nib dense-train --input shakespeare.txt --output nib.bin --tokenizer tokenizer.json \
  --init-dense nib.bin --epochs 1 --max-samples 20000 --batch-size 128 --lr 0.005

Smoke test a server

nib serve --model nib.bin --tokenizer tokenizer.json --host 127.0.0.1 --port 8092
